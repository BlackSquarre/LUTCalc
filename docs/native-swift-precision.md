## 1. 如何解释“精度不低于现在”

固定同一输入、曲线版本、色域、曝光、调节顺序、信号范围、LUT 域、网格、插值和输出格式后，验证以下独立层次：

| 层次 | 比较对象 | 要求 |
| --- | --- | --- |
| 算法语义 | 官方定义、已知现有行为 | 不遗漏标度、范围、适应、调节或裁剪规则 |
| 数值计算 | 序列化前 Double 结果 | 满足现有严格门槛和独立参考误差要求 |
| LUT 离散近似 | 网格间采样的 LUT 与连续变换 | 同网格、同插值条件下不引入迁移退化 |
| 文件编码 | 写出后由独立读取器恢复的数值 | 不增加可避免的量化损失；格式固有量化单独计量 |
| 交互预览 | 显示转换前后的指定阶段数据 | 独立误差预算，不参与导出精度背书 |

只比较截图、只检查一个中灰点、只跑恒等 LUT 或只比较导出文件哈希都不足以证明完整精度。更高位宽也不能修复错误公式或错误色彩空间。

“无退化”是对已声明输入域、功能矩阵与参考数据的验证结论，不是对任意浮点输入、任意软件和所有设备的数学全域证明。未覆盖的范围明确列出，发布支持范围必须与验证范围一致。

## 2. 三类参照与来源

### A. 现有引擎行为基线

- 冻结 `js/` 源文件、三个 bundle、格式预设、内置二进制资源和现有测试数据的 SHA-256；记录 Node 版本、运行命令、设置、日期及可用 Git 状态。
- 工作区文件不能假设已经受 Git 跟踪；即使存在 commit，也必须保存实际参与测试的文件哈希。
- 分别抽取散装实现、实际页面 bundle、外部/内联 Worker 路径。发现不一致时登记偏差，选择并记录参照实现；不能拼接不同版本的输出构成基线。
- Node 工具运行真实的参数设置和 gamma → colourspace → gamma 管线，加载真实 `.labin` 资源（仅开发环境的旧引擎基线）；不把矩阵单测当作完整管线测试。
- 保存序列化前结果，建议以明确 little-endian Float64 二进制加 JSON 元数据落盘，避免十进制格式先损失精度。

### B. 独立标准参照

优先使用厂商原始技术资料、ACES/标准原始实现及有来源的参考 LUT。每个参照保存 URL/文件名、版本、哈希、公式和适用范围。风格 LUT 只验证该风格，不充当 Log 曲线逆函数的参照。

现有 [D-Log2 fixture](../tests/fixtures/dlog2-reference.json)和[验证说明](dlog2.md)应原样纳入第一批对照。它们已有独立 Python/NumPy 计算结果，但不应误称为任意精度数学参照。

对临界分段、病态矩阵和数值优化，计划使用独立的高精度离线计算器，例如锁定版本的 Python `mpmath`。以 80 位十进制工作精度起步，必要时用 120 位重算检查收敛；将结果正确舍入到 Double 后形成夹具。公式推导不得从待测 Swift 实现机械复制。Node/Python 仅用于开发验证，不进入最终 App。

### B.1 纯算法与来源冲突的额外门槛

- 官方 LUT、旧 `.labin` 和样本夹具只作为研发参照，不进入原生 App；也不能改写成内嵌数组后参与内置曲线求值。
- 公开公式、厂商参考代码和厂商显示 LUT 分别登记；风格渲染与技术解码不能互作真值。
- 若白皮书与参考代码冲突，记录版本与最差差异，先裁决适用范围。已发现 OPPO O-Log2 的低段与常数不一致，见[资料问题清单](colour-research-2026-09-23.md)。
- 从规范原色计算 Double 矩阵；与厂商截断矩阵的偏差单独测量，不能把复现四位小数当成最高精度目标。
- 只有采样表的旧功能，不足以证明某个新连续算法全域等价。拟合模型未经显式审查与冻结误差门槛不得作为正式替代；不能通过增大节点数或减少样本掩盖差异。
- 没有足够来源的旧功能保持“公式缺失／待研究”，阻止该功能或全量迁移被标记完成。新增曲线仍逐项验证，不能用新增数量抵消旧功能未完成。

### C. 性质与实际工作流

验证合法定义域内的可逆性、应当单调的曲线、规定连续的分段边界、灰轴、原色、矩阵方向、范围映射、LUT 轴序和实际目标软件解释。非可逆裁剪/风格曲线不得套用可逆性断言。

## 3. 浮点与算法规则

1. 最终生成路径使用 `Double`，包括参数反序列化、数学常量、矩阵、插值、反求和块缓冲区。除格式明确规定的最终量化外，不得降为 Float/Float16。
2. 不使用 UI 格式化后的字符串回填计算参数；不提前保留小数，不把中间结果夹紧到 0...1。
3. 保存资料给出的有效数字。资料中的小数若是规范定义，应按其定义使用；未经证实不得自行补位或换成拟合常数。
4. 矩阵约定为列向量乘法，存储顺序单独明确。转换 `simd_double3x3` 的列布局时用非对称样例验证，不能只测单位矩阵。
5. 白点适应模型、输入输出白点和操作顺序显式保存。白点相同不代表可省略全部色域转换。
6. 保留定义允许的负数、超白和 HDR 值。区分曲线自身定义的限制、用户裁剪、格式量化及屏幕显示裁剪。
7. NaN、Infinity、无效域和反求失败必须返回可诊断结果；不得以零填充掩盖。数学上确有奇点的输入应由能力定义明确拒绝。
8. 求逆/求根记录收敛、残差、迭代上限和适用区间；接近奇异的自定义色域矩阵不能只靠“行列式不为零”放行，须结合条件估计和误差界。
9. 优先评估 `log1p`、`expm1` 等减少消减误差的公式，但替换前后均须和独立参照比较，不能只凭等价代数式认定提升。
10. 不开启未经验证的快速数学近似或允许任意重排的优化。SIMD/Accelerate 采用 double 路径；是否融合乘加按数值验证结果决定，不要求不同系统 libm 的结果逐位相同。
11. 固定请求的分块数量和任务完成顺序不得影响样本坐标、算子顺序或输出顺序。
12. 旧版内部线性标度、HDR 亮度单位及 legal/data 映射必须用类型或显式元数据表达，不能混用百分比、归一化信号与 nits。

Apple 的 [Double](https://developer.apple.com/documentation/swift/double)和[双精度 SIMD 文档](https://developer.apple.com/documentation/accelerate/double-precision-floating-point-vectors)支持相应类型与精度注意事项。现有 JS 使用 Float64，因此本方案不声称换语言即可提升数值精度。

## 4. 比较指标与首批硬门槛

对测试域中的样本 `x`，保存旧结果 `old(x)`、新结果 `new(x)`、独立参照 `ref(x)`。至少报告最大绝对误差、归一化误差、均方根误差、P99、失败样本数、最差输入与通道；ULP 作为辅助诊断，接近零时不单独用于判定。

现有测试使用的尺度化误差为：

```text
scaledError(a, b) = abs(a - b) / max(1, abs(b))
```

这对小值采用绝对界、对大值采用相对界。它不能替代暗部专项误差指标，因此另记录接近黑位/分段点的绝对误差及编码后的码值误差。

| 检查 | 硬门槛或处理方式 |
| --- | --- |
| 现有 D-Log2 标量、向量、矩阵、1D 对照 | 保持原测试 `scaledError ≤ 2e-12`，不得放宽 |
| 现有 D-Log2 33³ 宽色域往返 | 保持原测试每通道误差门槛 `2e-10` |
| 现有 D-Log2 10 位小数文本恒等输出 | 保持原测试 `1e-9`；它只适用于该序列化用例 |
| DCTL 四位矩阵参照 | `1.1e-4` 只用于比较那个已经舍入的参考，不能作为新引擎普遍门槛 |
| 新的解析曲线和良态矩阵 | 以 `2e-12` 尺度化误差作为初始设计门槛；先对独立参照验证可达性并冻结逐项阈值 |
| 包含多级操作/插值/反求的复合管线 | 按阶段误差传播和实测基线冻结逐项阈值，禁止套用一个宽松全局值 |
| 非有限输出 | 声明有效输入域内为 0 个；无效输入返回明确失败 |
| 同一平台、同一工具链、同一请求 | 重复执行与不同分块/并发数的序列化前结果相同；不依赖调度顺序 |
| macOS 与 iOS、不同工具链 | 按逐项浮点门槛比较；文件结构/整数编码等可精确项仍需精确一致 |

所有尚待冻结的逐项阈值都必须在对应 Swift 实现验收前完成，不能在看见新实现失败后自动调大。没有阈值与输入域的功能不能标记精度验收完成。

对于有独立参照的样本，除兼容误差门槛外，增加不退化检查：

```text
abs(new - ref) <= abs(old - ref) + B_round(x)
```

`B_round(x)` 是该公式/输入域预先确定的浮点舍入预算，依据运算敏感性、高精度参照及目标平台数学库差异建立，不得简单等于宽松的全部管线容差。严格为零的旧误差附近允许预算内数值等价，不宣传这种差异为提升。

更高精度的认定需要：同一测试集合和度量下，改善超过参照不确定度与 `B_round`，且没有新的超预算退化。若无法取得独立参照，只能报告兼容通过，不能宣称更准确。

## 5. 输入集合与覆盖矩阵

### 曲线与范围

- 每条有效曲线分别测编码/解码、标量/批量、data/legal 和有效输入输出方向。
- 遍历 10-bit 全部 1024 个码值、12-bit 全部 4096 个码值；按曲线定义域补充更密采样。
- 分段点精确值、`nextDown`、`nextUp`、有物理意义的邻域值；零、负零、黑位、中灰、白位和有效域上下界。
- 对数分布暗部/HDR 样本，均匀与固定种子随机样本，定义允许的负数和超过 1 的值。
- 用独立公式核对范围转换，例如本项目 10-bit legal 的黑白码 64/940 与全码 0/1023；不要把所有位深硬编码为同一常数。
- 每个有状态参数族覆盖有效边界，例如 ISO/EI、PQ/HLG 参数和可调 gamma。

### 色域与矩阵

- 每个矩阵/特殊色域测试黑、白、中灰、原色、互补色及负通道；适用时检查逆变换和中性轴。
- 覆盖 D65/D60/D50 等白点变换、各实际使用的适应模型，以及自定义原色/白点。
- 不以所有有效 RGB 坐标或原色色度都在 0...1 为假设；拒绝策略基于数学有效性和条件数。
- 建立全体可兼容输入输出色域组合的稀疏矩阵/样本检查，代表性组合再执行完整 LUT 网格。

### 端到端与调节

- 基础 1D/3D 各跑恒等、非恒等与跨厂商链路，覆盖 S-Log3、LogC4、D-Log2、Apple Log、V-Log、Rec.709、sRGB、PQ/HLG 等第一批曲线。
- 相机默认值经“选择预设 → 有效设置 → 完整管线 → 文件”整条路径验证，覆盖格式预设对范围的覆盖行为。
- 每个调节单独测中性、典型、边界参数；组合采用成对覆盖，并为非交换算子增加顺序敏感样例。
- 17³/33³/65³ 覆盖节点，网格间额外采样；遍历全部曲线的标量检查与代表性完整网格检查分层运行，避免把完整网格数量当作功能覆盖率。
- LUTAnalyst 使用可逆合成 LUT、非可逆 LUT、强裁剪、噪声、畸变与病态输入检查恢复误差和失败行为。

## 6. 插值和采样误差

保留现有 cubic/tricubic、tetrahedral、linear/trilinear 等实际支持模式及其边界和外插语义。给每种模式独立 ID；不得将 Core Image 默认采样方式当作其他插值的等价实现。

在固定坐标集合上比较：

1. 原始连续变换 `F(x)`。
2. 旧版生成、按指定模式插值的 `L_old(x)`。
3. 新版生成、同一模式插值的 `L_new(x)`。

量化节点计算误差与 `abs(L(x)-F(x))`，使用独立坐标、非轴对称样例、边缘/角点和高曲率区域。仅有样本 LUT 的风格没有已知连续真值时，报告对已有数据及已定义插值的兼容性。

更高阶插值可能过冲，密度增加也不能恢复源 LUT 未包含的细节。129³ 属于可选质量配置，只有格式/目标软件允许且测试表明受益时启用；不能用增加网格掩盖同网格下的迁移误差。

## 7. 序列化与量化

### 十进制格式

- 原生高保真策略：采用能往返恢复有限 Double 的最短十进制表示，最多需要 17 位有效数字；不强制每个值输出相同位数。
- 对不接受科学计数法的目标解析器输出等值普通十进制形式并验证往返，不将其简单截断为固定小数位。
- 提供旧版固定小数位兼容策略，保留请求的位数和舍入行为。固定小数位策略允许格式规定的量化，但不能比同设置旧输出更差。
- 区域设置固定小数点为 `.`、无千位分隔；明确 UTF-8、换行、标题转义、负零以及 NaN/Infinity 拒绝规则。
- 高保真通用文本在本方读回时应恢复相同有限 Double 值（明确规定的负零规范化除外）；真实目标软件可能内部降精度，需单独测量和报告。
- 旧版 UI 可填很多小数位不意味着超出 Float64 的有效精度；改用清楚的导出策略描述，不把打印位数当作计算位宽。

固定小数 `p` 的理想最近舍入步长为 `10^-p`，误差通常不超过半步长加转换舍入预算；具体边界必须测真实格式化器。不能把该界用于域裁剪、插值或二进制格式。

### 整数和二进制格式

- `.3dl`、`.vlt`、`.ncp`、`.labin` 等逐项记录量化步长、缩放、字节序、允许范围、上溢规则及舍入方式。
- JS `Math.round` 与 Swift 默认 `rounded()` 在负半整数上的语义可能不同，格式兼容必须显式实现并测试相同规则。
- 半步长附近用高精度参照裁决量化边界；不得对所有整数结果粗略允许 ±1 码值。
- 明确 `.labin` 样本与矩阵的不同缩放因子；写出溢出要报错或执行明确的格式规则，不能绕回整数范围。
- 每种格式独立检查 R/G/B 遍历顺序、尺寸、输入域、头部、注释、样本数与解析后结果。
- 同一读写器往返可能共享同一个错误，需增加独立读取器或已知文件夹具及实际目标软件测试。

## 8. 预览与取样的单独验收

数值取样由 CPU Double 内核提供，可选择查看输入、变换后和显示映射后的指定值。图像解码精度、预览 LUT 采样、Core Image 工作像素格式和最终屏幕输出分别测量。

Core Image [workingFormat](https://developer.apple.com/documentation/coreimage/cicontextoption/workingformat)可配置工作像素格式，但不意味着获得与 CPU Double 一样的计算精度。交互路径优先评估浮点工作格式；支持情况、性能和误差须在设备上验证。

GPU/系统滤镜路径对比同插值语义的 CPU 结果，记录 RGB 绝对误差、码值误差和必要的感知指标。感知指标仅在明确白点/显示条件且适用的颜色域计算，不把任意 Log/负 RGB 直接输入 Delta E 公式。

预览阈值由首批实机基线建立，独立于导出门槛。未达标的预览功能回退到 CPU 路径或标记不支持，不得降低最终导出门槛。HDR/EDR、广色域显示、透明边缘、缩放取样和重复色彩转换必须有专项样例。

## 9. 偏差处理与版本

每个超门槛偏差建立记录，包含最小复现、源哈希、参数、最差输入、旧/新/参考值、阶段定位、影响和处理决定。

- 移植错误：修复 Swift 实现。
- 旧实现或常量有误：用独立证据证明，作为有版本的算法修正；报告相对旧版的差异与相对标准的改善，不能静默改基线。
- 源资料冲突/不足：保留出处与支持限制，不能选择恰好让测试通过的参照。
- 舍入或数学库差异：只在预先确定的舍入预算内认定数值等价。

原生项目记录引擎/算法版本；升级项目若改变结果，必须能识别和解释。必要时保留明确的旧算法配置，但默认新项目使用已验证的正确实现。不能借“兼容模式”隐去新版本的退化。
