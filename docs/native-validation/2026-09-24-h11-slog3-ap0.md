# H11 Sony S-Log3 / S-Gamut3.Cine → 线性 AP0 阶段验收

日期：2026-09-24。状态：Sony 官方 S-Log3 到线性 ACES AP0 的跨色域 Double 链路在标量/矩阵、10 个 RGB 点与 33³/65³ CUBE 全网格通过；完整 ACES 输出变换或旧引擎全功能不在此结论内。

## 来源、契约与实现

采用 ACES 项目中由 Sony 提供的 [`CSC.Sony.SLog3_SGamut3Cine_to_ACES.ctl`](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/CSC.Sony.SLog3_SGamut3Cine_to_ACES.ctl)，变换 ID 为 `urn:ampas:aces:transformId:v2.0:CSC.Sony.SLog3_SGamut3Cine_to_ACES.a2.v1`。其 S-Log3 逆函数与前一阶段 Sony 技术摘要一致，声明 S-Gamut3.Cine 与 AP0 原色，并使用 CAT02。矩阵构造参照 ACES [`Lib.Academy.ColorSpaces.ctl`](https://github.com/aces-aswf/aces-core/blob/main/lib/Lib.Academy.ColorSpaces.ctl)。两份原文仅归档于 `research/`，SHA-256 分别为 `e86553acc9bb56fdf042310a0bd12dce9eb3f1e363895e4fc91fc6cde4be530c`、`4f07503e00127b00719416d63446d9a6b504798111d94f3860eb74754b6fb00a`，不进入 App。

先用独立 Python `Decimal` 以 **CTL 的行向量约定**计算原色→XYZ、CAT02 白点适应和 XYZ→AP0，再转为 Swift 列向量矩阵的行主序作比较。矩阵和 10 个含灰轴、非对称原色、负值及高亮的 RGB 点在 80/120 位十进制精度下舍入到同一 Double。冻结最大尺度化误差门槛 `2e-12`。先扩充 Swift 契约，确认矩阵与 10 点均通过，但因跨色域预设尚未登记而失败；随后加入稳定预设 `sony.slog3-to-linear-ap0.v1` 与研发 CLI 别名。

全网格核对由独立 Python 逐行解析 CUBE，并对每个节点按 Sony 逆函数、曝光 +1、冻结的高精度 CAT02 矩阵计算参考 RGB。CUBE 是任务即时生成的产品输出；没有把官方 LUT、旧 `.labin` 或等价采样表加入计算路径。
