# 2026-10-02 ARRI Log C 公开紧凑公式内核阶段验收

## 范围

UI 继续暂缓。本包新增纯 Swift Double `ARRILogCCompact`：按公开厂商公式及参数，提供 SUP 2／SUP 3、sensor signal／scene exposure、11 个 EI（160–1600）的 44 组解析配置。保存 7 个解析系数并直接计算 log／幂／仿射分段；产品不读取研发参照、PDF、采样文件或旧引擎。

这是公开公式内核阶段。**尚未加入 TransferID、TransformPlan、转换预设、项目参数或完整相机模型；原生项目仍为 schema 16。** 公开紧凑式本身不能代表所有实际相机高光或高 EI shoulder，不能据本包将 FULL-01／FULL-02 或完整 Log C 迁移勾选。

算法身份分别为 `arri.logc-sup2-compact-published.v1`、`arri.logc-sup3-compact-published.v1`；配置还须区分线性域和 EI。仅接受文档列出的离散 EI，不推断任意 EI，不插值参数或回退到 EI 800。SUP 2 的 raw camera RGB 与 SUP 3 AWG 语义没有混用。

## 来源、分支与已知差异

实际归档 ARRI 官方 2017 PDF 和同名 2012 厂商文档公开镜像，PDFKit 提取文本；两份 SUP 3 参数逐行相同。URL、下载／重定向／时间、SHA 及范围见[来源和最小复现研究](2026-10-02-logc3-shoulder-research.md)。

按文档保留 `x > cut`、`t > e*cut+f` 分支；Double 准备 `cut` 与 `e*cut+f`，选定分支的计算值另用 80／120 位 Decimal 独立验证。负值和超白保留，不在此内核做传感器或格式裁剪；NaN、Infinity、不可有限表示的结果拒绝。公开参数接缝不修补：44 组最大约 `1.3566431744105323e-6`，SUP 3 scene EI 800 为下降接缝约 `−2.501721051706429e-7`。本包不声称连续、唯一反求或逐位旧兼容。

旧 `js/gamma.js` 实际最小复现显示 EI 1600 输入 1 的标量／数组编码差 `0.34460857517167864`；Data=1 与 1.nextUp 解码跳变 `−4.074569019274463`。真实高 EI shoulder 的公开完整公式／独立参照尚未取得，按项研究阻塞，不使用厂商 LUT 补足。

## 契约、失败与修复

先写 3 项契约，`contract-red.log` 实际退出 1：内核接口尚未实现。随后实现解析式，`debug-first.log` 3 项通过。

首轮独立生成器退出 0，但将 decode(100) 的不可表示结果保存成 `inf` 字符串；该 JSON 已另行保留为 `independent-initial-with-overflow-probes.json`，不作为最终有限数值参照。修正生成器，对有限参照增加显式检查，并将 decode(100) 转为 **全部 44 配置的 nonFinite 拒绝契约**，没有删除实际 10/12-bit 码或网格节点、降低门槛。另验证全部配置的有限最大输入溢出拒绝、未知 EI、NaN／Infinity、负值／超白、分支和接缝差异。

最终 `debug-final.log` **3 项／0 失败**，`release-after-overflow.log` 全包 **485 项执行／0 失败／2 项既有可选夹具跳过**（旧 `.labin` 研发夹具、公开 NCP 样本）。修改溢出契约后完整 Release 已复跑；产品源码仍对应此次三平台构建。
