# H11 Rec.2100 HLG 33³/65³ 全网格阶段验收

日期：2026-09-24。此项承接 [HLG 场景曲线标量阶段验收](2026-09-24-h11-hlg.md)，只验证 BT.2100-3 表 5 的场景 OETF/逆 OETF 在 Rec.2020 同色域、Data→Data、曝光 +1 档的 Double 最小计划。标准原文归档于 `research/colour/2026-09-24/itu-bt2100-3-2025.pdf`，SHA-256 为 `f0668803dce2cd67e3780efbe97494c776b7d6b680733c8237fee364f2d412c3`。

## 契约和首次失败

新增 `LUTHLGChecks` 作为独立检查入口。检查器私有地按 BT.2100-3 表 5 重写逆 OETF、曝光倍乘和 OETF 参照；遍历单位域的 33³ 与 65³ 每个 RGB 节点，并逐通道比较 `TransformPlan.evaluate`，尺度化误差定义为 `abs(actual-expected)/max(1, abs(expected))`，冻结阈值保持 `2e-12`。参照函数不调用被测 `HLGTransfer`，网格索引沿用公共 `Grid3D`。

第一次运行在 33³ 节点 1 的绿色通道失败：参照为 `0`，计划得到 `3.1074387522039793e-10`。原因是同色域仍经过 Rec.2020→工作色域→Rec.2020 两次矩阵，近黑残留串色被 HLG 平方根分支放大。`TransformPlan` 现对输入和输出色域相同的计划使用恒等矩阵，仍执行原有各阶段、曲线和曝光；同色域无色域转换本来就是该最小计划的数学语义。未改变 HLG 公式或误差门槛。

## 结果

- `swift run -c release --package-path Native/Packages/LUTKit LUTHLGChecks`：33³ 的 35,937 节点及 65³ 的 274,625 节点均通过；两者最大尺度化误差为 `0`。
- `swift test -c release --package-path Native/Packages/LUTKit --filter 'NumericContractsTests|RegistryContractsTests'`：新增黑位零通道回归契约后，11 项数值契约及 3 项注册契约通过。
- `swift run -c release --package-path Native/Packages/LUTKit LUTCatalogChecks`：通过，12 曲线、9 色域、12 预设。
- `LUTHLGChecks` 已接入 `tools/native-validation/verify-native-subset.sh`，位于 H11 Apple Log 曲线检查之后。接线后 `bash -n` 语法检查通过，并再次单独运行 `LUTHLGChecks`，33³/65³ 全节点均通过；完整发布入口由主任务统一重跑。

检查直接比较 Double 计划输出，没有通过文本 CUBE 序列化、解析或目标软件导入。因此当前结果不覆盖文件方言、量化、插值、跨色域、旧版完整链、OOTF、显示 EOTF、HDR/EDR 实屏或双端设备。H11、CORE-03、UI-06 和发布门槛仍不关闭。
