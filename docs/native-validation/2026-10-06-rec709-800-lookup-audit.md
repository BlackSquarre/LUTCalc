# Rec709 (800%) 直接查表等价性审计

## 范围

本轮只复核旧 `LUTGammaIOLUT` 注册 `Rec709 (800%)` 的 `rec`／`out` 两条
样条，比较公开 Rec.709 OETF、BT.1886 reference-display EOTF 与旧 Legal/Data
包装。没有把样条节点复制到 Swift，也没有改变 45 项查表阻塞台账。

## 旧行为与独立对照

旧实现位于 `js/gamma.js:LUTGammaIOLUT`：输入先经过 S-Log3 风格的
SimpleLog bridge，再对 `out` 样条求值；反向路径先对 `rec` 样条求值，再
执行相同 bridge 的逆函数。`linToLegal` 还额外使用固定
`(x - 0.06256109481916) / 0.85630498533724` 包装。这不是单一的 Rec.709
OETF，也不是 BT.1886 显示 EOTF。

按旧 bridge 计算几个有限 scene 输入，并用旧 `out` 样条的三次求值与公开
公式对照：

| scene 输入 | 旧 `out` 样条 | Rec.709 OETF | BT.1886 γ2.4 |
|---:|---:|---:|---:|
| 0.018 | 0.1562143794 | 0.0812479440 | 0.0000649612 |
| 0.180 | 0.4201830666 | 0.4090077289 | 0.0163175147 |
| 0.500 | 0.6662182222 | 0.7055150899 | 0.1894645708 |
| 1.000 | 0.8261006111 | 1.0000000000 | 1.0000000000 |

旧样条在 0.18、0.5 和 1.0 都与两个公开候选明显不同；其低端还保留独立
的 Log bridge 和负值行为。`800%` 的高光范围、输入／输出样条配对、固定
Legal 包装和实际设备语义没有公开连续定义或独立 17³／33³／65³ 参照，不能
从 Rec.709、BT.1886 或通用 gamma 推导。

## 失败契约

新增 `RegistryContractsTests/testRec709800LookupCannotAliasRec709OrBT1886`，
Release 执行 1 项、0 失败。它确认 `Rec709 (800%)` 不解析为 transfer、色域
或预设，同时确认独立 `Rec.709 (LUTCalc legacy)` 与 `BT.1886` 身份仍存在。

实际命令：

```sh
swift test --package-path Native/Packages/LUTKit -c release \
  --filter RegistryContractsTests/testRec709800LookupCannotAliasRec709OrBT1886
```

结果包：`docs/native-validation/artifacts/2026-10-06-rec709-800-audit/release.log`；
SHA-256：`9e364f236d18d7d1edd416e6e4c3b912fe11c222c245137b72f243afef02a7a9`。

## 结论

该失败契约只关闭误把 `Rec709 (800%)` 别名成 Rec.709 或 BT.1886 的回归风险，
不关闭任何查表替代项；直接查表替代仍为 `0/45`。取得公开连续定义、范围／
设备语义和独立网格参照前，不实现 Swift 算法。Goal 保持 `active`。
