# H11 sRGB 单条曲线阶段记录

日期：2026-09-23。来源：[W3C CSS Color 4 sRGB 扩展传递函数、原色与 XYZ 逆矩阵（2026-09-13 候选推荐草案）](https://www.w3.org/TR/2026/CRD-css-color-4-20260913/#predefined-sRGB)；旧兼容行为来自 `js/gamma.js` 的 `LUTGammaGam` 注册与 `linToLegal`/`linFromLegal`。本次已验证标量与无调节变换计划；没有把 sRGB 加入 App UI。

## 语义与版本

`srgb.w3c-extended.v1` 使用 W3C 的符号对称负值扩展：线性绝对值 `≤0.0031308` 时乘 `12.92`，其余取符号并用 `1.055×|x|^(1/2.4)-0.055`；逆函数在编码绝对值 `≤0.04045` 时除以 `12.92`，其余使用带符号的 `((|v|+0.055)/1.055)^2.4`。不隐式裁剪负值或超白。`srgb.lutcalc-legacy.v1` 明确保留旧版正值编码分段 `0.0031308`、解码分段 `0.04015966` 和负值线性延拓。两者是不同的算法版本，不能静默互换。

最小偏差：编码值 `0.0403` 的旧解码为 `0.003119012091626794`，W3C 解码为 `0.0031191950464396286`，差约 `1.8295481283e-7`。编码值 `-0.1` 的旧解码为 `-0.007739938080495357`，W3C 扩展解码约为 `-0.010022825574869039`；负值延拓的差异尤其不能只用普通 `[0,1]` 测试掩盖。

## 第二段：计划、色域与完整 CUBE

先新增 `generate-srgb-plan-reference.py`，以冻结 DJI `toXYZ` 参照及 W3C 提供的有理数 `XYZ_to_lin_sRGB` 矩阵，按另一条 Python 数值路径生成 4 个非恒等输入点。夹具明确冻结标准/旧兼容数据域、10/12 位视频域及曲线前的线性 sRGB。阈值沿用既有 `2e-12` 尺度化门槛，未放宽。随后扩充 `LUTContractChecks`，先运行，按预期因缺少新 ID 而编译失败，再实施 Swift 代码。

`TransformPlan` 新增两个版本化传递函数 ID、`srgb.d65.v1` 色域和 8/10/12 位范围参数。W3C 版在场景线性数值上直接编码；旧兼容版在曲线边界显式调用 `sceneToLegacy`，输入方向显式调用 `legacyToScene`。该 0.9 适配只在旧兼容版本发生。输出 stage 13 的单位从场景线性变成编码数据，stage 19 才应用视频范围。`LUTReferenceCLI` 新增 `dlog2-srgb-w3c` 研发预设，App UI 仍不显示。
