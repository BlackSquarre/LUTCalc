# H11 Rec.2100 HLG 场景曲线阶段验收

日期：2026-09-24。范围仅为 BT.2100-3 的 HLG 场景 OETF 与逆 OETF 的 Double 标量、注册和最小曝光计划；不是 HLG 显示 EOTF、OOTF 或 HDR 屏幕验收。

## 公式来源与边界

- 独立来源：[ITU-R BT.2100-3 官方下载页](https://www.itu.int/rec/R-REC-BT.2100/en)，原文归档于 `research/colour/2026-09-24/itu-bt2100-3-2025.pdf`；PDF 15 页、678999 字节，SHA-256 `f0668803dce2cd67e3780efbe97494c776b7d6b680733c8237fee364f2d412c3`。
- 表 5 的场景 OETF：`0 <= E <= 1/12` 时 `E' = sqrt(3E)`；`1/12 < E <= 1` 时 `E' = a ln(12E-b)+c`。`a=0.17883277`，`b=1-4a=0.28466892`，`c=0.5-a ln(4a)`（注 5c 给出舍入值 `0.55991073`）。逆函数在 `E' <= 0.5` 时为 `E'^2/3`，其上为 `(exp((E'-c)/a)+b)/12`。
- 数值语义为单通道相对场景线性，标准名义域 `E,E' in [0,1]`。正向输入及反向输入的负值明确返回 `invalidDomain`，非有限输入/溢出返回 `nonFinite`。正值超过 1 时按相应解析分支延拓，不裁剪；这是本实现的研发域外策略，不将其宣称为标准域内精度。BT.2100 注 5h 允许制作交换过程中编码信号超过 1，并提醒不得无条件裁剪。负编码信号的 PLUGE/显示行为须在完整 EOTF 和黑位参数工作包单独处理。
- 旧版 `js/gamma.js:LUTGammaHLG` 带有 BBC 系数、data 换算及不同的分段行为；这里没有声称与旧版输出等价，也没有将旧版当作独立真值。`rec2100.hlg.v1` 只进入研发注册和 `rec2100.hlg-exposure-one.v1` 最小计划。未接入 SwiftUI 可用曲线列表。

## 先失败后实现

先在 `NumericContractsTests.swift` 写入标量与注册/计划契约，运行目标测试因缺少 `HLGTransfer` 无法编译；随后按测试目标依赖，将注册/计划检查移到 `LUTCatalogTests`。实施文件为 `HLGTransfer.swift`、`TransformPlan.swift`、`AlgorithmCatalog.swift` 与相应两份 XCTest；`LUTCatalogChecks` 的注册数量更新为 12 曲线、9 色域、12 预设。没有修改既有误差门槛。

独立参照使用 Python `decimal` 70 位精度，按 BT.2100 表 5 直接求值，冻结点包括：`E=0.01 -> 0.17320508075688773`、`E=0.18 -> 0.6723581321276545`、`E'=0.75 -> 0.2649625604210072`、`E'=1.2 -> 3.010977610099849`，以及同色域一档曝光后的 `E=0.36 -> 0.8093982436264028`、`E=0.5 -> 0.8716434708741772`。所有断言保持 `2e-12` 绝对门槛；覆盖零点、分段点及 `nextUp/nextDown`、负值、超 1、非有限值、10/12-bit 共 5120 个全码往返。
