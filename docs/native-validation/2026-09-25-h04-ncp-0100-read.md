# H04 `.ncp` 0100 只读子集阶段记录

日期：2026-09-25。范围：FULL-06 的 Nikon Picture Control `.ncp` 格式调查与纯 Swift 只读子集。此项未接入导入界面或导出服务，不代表 Nikon 设备兼容。

## 新的独立证据

- 旧写出 `js/lut-ncp.js`（SHA-256 `7fe9a89b4e87dbc4d951b1dca52eebb92b19f98031f028ca05d0105dbd3d3441`）仍是旧行为来源。此前调查见[阻塞记录](2026-09-24-ncp-research-blocker.md)。
- [coderat 的 `dumpncp.pl`](https://github.com/simeonpilgrim/nikon-firmware-tools/blob/main/nfiles/dumpncp.pl)于 2014 年创建，独立于本仓库 JS；它按 big-endian 记录头、36/578 字节记录、控制点表和 256 个 16-bit LUT 码解析 `0100` 文件。
- [Horshack 公开样本](https://github.com/horshack-dpreview/NikonPictureControlsDev/blob/main/Picture%20Controls/Horshack_Linear.NCP)长 638 字节，SHA-256 `ab63c0581fa29424f0c7baed1c325930ca1b79846b248e60a2f0169093c952e9`。样本的名称为 `HS Linear v01`，Neutral 基础代码 `0x03c2`，控制点数为 2，LUT 第 0/127/255 码为 162/11812/32767。独立 Perl 解析器读出相同记录长度、名称、基础风格、调整字段和控制点。另两份同源公开样本 `Horshack_RawLinear.NCP`、`Horshack_Invert.NCP` 也均为 638 字节；后者的 LUT 递减，故读取时不要求单调。
- 样本说明没有提供具体 Nikon 机型、固件或官方软件导入回执。公开社区解析和样本足以核查这个只读布局，不足以承诺写出文件可被任意设备接受。

## 冻结的读取范围

`NCP0100Reader` 仅接受精确 638 字节、`NCP\0`、big-endian 记录 `1/36` 与 `2/578`、ASCII 版本 `0100`、观测到的 `0x49 0x30` 标记及四字节零结尾。读取 20 字节 NUL 补齐的可打印 ASCII 名称、九种已知基础风格代码、8 个原始调整字节、最多 28 对 x 严格递增的控制点、256 个 0…32767 的 big-endian LUT 码。码值以 `Double(code)/32767` 暴露，不把单通道 LUT 猜测成 RGB、输入域或相机显示输出。未知字节不被解释，NP2/NP3、其他版本、未知风格和其他布局拒绝。

旧 JS 固定写 18 对控制点，而公开样本仅有 2 对；因此它不能作为所有 NCP 的写出模型。旧版 `0x49 0x30`、修改标志、调整字节、标题编码和压缩控制点与完整 LUT 的设备关系仍未充分解释。没有添加新写出器或厂商采样表。
