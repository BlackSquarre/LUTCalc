# ICC `mft2` 255 点网格边界验收

## 范围

本轮只处理 ICC.1 `mft1`/`mft2` 变换的网格点字段边界。该字段是无符号
8 位值，规范允许 2 至 255 个网格点；此前 Swift 实现将上限人为限制为
64，导致合法的 65 至 255 点用户导入 profile 被拒绝。没有扩展 UI、BPC、
gamut mapping、ColorSync 或任何内置 LUT 资源。

## 契约先行与实现

新增 `ICCMFTContractsTests.testMFT2AcceptsICCMaximum255PointGridForOneDimensionalProfile`，
用一进一出、255 点的最小 `mft2` profile 验证解析、线性 CLUT 插值和输出误差。
原有极端通道/资源长度拒绝契约保留，并改用 255 点字段验证资源检查仍在
`checkedPower`、`checkedProduct` 和 `checkedSum` 执行。

生产代码将网格检查从 `2...64` 放宽为规范边界 `2...255`，不改变资源上限
（16 MiB）和 Double 插值路径。

## 实际验证

命令：

```sh
swift test --package-path Native/Packages/LUTKit -c release --filter ICCMFTContractsTests
```

工具链：Xcode 27 / Swift 6，macOS arm64。

结果：`ICCMFTContractsTests` 15 项通过、0 失败，退出码 0。255 点样本
`0.375` 的输出绝对误差小于 `2 / 65535`；日志保存在
`docs/native-validation/artifacts/2026-10-06-icc-mft-grid255/release.log`，
SHA-256 为 `fafb936cf408f8e6cf90bfea4f24b7fa98e3b9f65432be47b38b2cc479aa5006`。

## 未覆盖范围

本项只关闭 `mft` 网格点上限边界，不代表完整 ICC profile class、全部
rendering intent、BPC、通用 gamut mapping、ColorSync、真实第三方 profile
逐码参照或 Goal 完成；这些范围继续保持未完成。
