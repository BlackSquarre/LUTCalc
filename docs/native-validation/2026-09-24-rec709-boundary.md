# Rec.709 分段边界研究记录

日期：2026-09-24。状态：数学语义已复现；官方逆函数仍为研究边界，旧兼容版已在后续阶段单独实现，不计 H11 全项完成。

## 来源与最小复现

[ITU-R BT.709-6 第 1.2 项](https://www.itu.int/dms_pubrec/itu-r/rec/bt/r-rec-bt.709-6-201506-i%21%21pdf-e.pdf)给出源端 OETF：`0 ≤ L < 0.018` 时 `V = 4.5L`，`0.018 ≤ L ≤ 1` 时 `V = 1.099L^0.45 - 0.099`。本次用 Python `Decimal` 80 位计算，左侧极限是 `0.081`，在 `L = 0.018` 的右侧值是 `0.08124794403514047768472779574563161255…`，中间有约 `0.00024794403514047768` 的编码空隙。原推荐文本没有为该空隙定义逆函数、负值或超白域外策略。

旧 `js/gamma.js` 的 `Rec709` 使用参数 `[1/0.45, 4.5, 0.099, 0.018, 0.081, 1.9]`，其 `LUTGammaGam` 编码按 `L >= 0.018` 选高段，解码按 `V >= 0.081` 选高段；这给空隙中的码值指定了旧行为，但不构成 ITU 指定的唯一逆。`js/gamma.js` 本次 SHA-256 为 `250017d8efe758f3555148ba9fcb923698add0ac7d9380fa290716eb98e0821e`；未修改旧源或夹具。

## 影响与下一步

受影响能力是 Rec.709 输入解码、10/12-bit legal/data 全码验证与负值/超白外推。不能把“官方 OETF”直接称为一条在全部 Double 上可逆的曲线，也不能用另一组连续常数静默替换。实现时应给旧兼容版单独稳定 ID，并分别验证旧真实行为与 ITU 定义域内的前向公式；官方版的逆函数及域外策略要另行明确并冻结测试，不将暂定策略暴露为已通过功能。该事项是 H11 的具体研究边界，不影响已经规范齐全的 D-Log2 与 sRGB 工作。

实际命令：`rg -n 'Rec709|LUTGammaGam' js/gamma.js` 并阅读对应注册及 `linToLegal`/`linFromLegal`；`python3` 使用 `Decimal` 80 位求两侧值。未运行原生测试或平台构建，本记录只有资料及数学复现。

后续旧兼容 ID、标量/全码和 33³/65³ 验证分别见[标量阶段](2026-09-24-h11-rec709-legacy.md)与[全网格阶段](2026-09-24-h11-rec709-grid.md)；这些结果没有改变官方逆函数空隙的研究状态。
