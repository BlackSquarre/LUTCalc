# ICC MPE 拒绝分支算法扫描

## 扫描范围

本轮只复核 `ICCMPETransform` 明确拒绝的处理元素和公式曲线，不涉及 UI、
BPC、gamut mapping、ColorSync 或任何内置采样资源。

## 已确认的规范边界

- `parf` 按 ICC.1:2022-05 Table 60 仅定义函数类型 0、1、2。当前实现对
  类型 3、4 返回 `unsupportedCurve`；这两个类型属于独立的 `para` tag，
  不能把参数数量直接套入 `parf`。
- `samf` 的首段没有前一段曲线值可作为隐含 `j=0` 起点，当前拒绝首段；
  末段使用前一段终值并延伸到归一化终点 1.0，已有独立契约覆盖。
- `matf` 的矩阵输入/输出通道数可不同，当前按声明通道数解析；零通道、
  越界长度和非有限 float 已有结构契约。
- 未知 MPE 元素、厂商扩展以及末端额外填充字节的兼容语义，当前没有同时
  满足公开规范和独立逐码参照的证据。

## 结论

本轮没有发现可安全新增的生产算法。放宽 `parf` 类型、首段 `samf` 或末端
填充处理都会引入猜测性语义，可能把 `para`/厂商扩展错误解释为标准 MPE。
保持现有拒绝边界，不新增测试以外的实现。完整 ICC MPE、真实第三方 profile
逐码参照和 Goal 仍未完成。
