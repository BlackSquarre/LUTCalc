# APP-03 注册表基础阶段记录

日期：2026-09-23。本阶段只登记已经有 Swift 解析实现的 4 条传递函数、3 个色域和 2 个研发预设，不把覆盖调查中的未迁移项目冒充可用能力。正式 UI 仍为草稿，没有新增选择项。

## 契约先行与实现

先新增 `LUTCatalogChecks`：要求稳定原始 ID/别名解析、未知 ID 不回退、来源非空、预设引用完整，并对重复 ID、重复别名、悬空引用拒绝。首次执行按预期因注册表类型尚不存在而编译失败。随后新增 `LUTCatalog/AlgorithmCatalog.swift`，以 `TransferID`/`ColorSpaceID` 的原始值作为唯一规范 ID，记录来源、线性参考标度和实际验证范围；研发预设持有不可变 `TransformSettings`。`LUTReferenceCLI` 改为通过注册表取得预设设置，避免在 CLI 再维护第二套输入/输出参数。

规范来源：D-Log2/D-Gamut2 来自 DJI ACES CTL `IDT.DJI.DLog2_DGamut2.a1.v1` 与既有独立夹具；sRGB 原色及标准扩展曲线来自 [W3C CSS Color 4 sRGB 章节](https://www.w3.org/TR/2026/CRD-css-color-4-20260913/#predefined-sRGB)；旧兼容版本明确指向 `js/gamma.js` 中 `LUTGammaGam` 的旧行为。来源文字不是打包进 App 的采样资产，`LUTCatalog` 只有 Swift 元数据和 ID。AP0 的完整规范来源与 Sony 内部工作色域的注册元数据仍需补齐。

实际执行 `swift run --package-path Native/Packages/LUTKit LUTCatalogChecks`、`swift run -c release --package-path Native/Packages/LUTKit LUTCatalogChecks`、`swift build -c release --package-path Native/Packages/LUTKit`，均通过。注册表的 4/3/2 数量、来源、别名、未知项、重复/悬空引用路径均由 Debug/Release 契约入口执行。再实际运行：

```text
swift run -c release --package-path Native/Packages/LUTKit LUTReferenceCLI --size 17 --output /tmp/lutcalc-catalog-cli-17.cube --preset dji.dlog2-to-srgb-w3c.v1
python3 tools/native-validation/verify-srgb-cube.py /tmp/lutcalc-catalog-cli-17.cube --size 17
```
