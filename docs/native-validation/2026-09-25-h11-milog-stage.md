日期：2026-09-25。状态：**Mi-Log 白皮书三段公式、Rec.2020 身份和线性曝光计划的本地数值验证通过；H11、手机型号范围、完整 ACES 工作流、双端交互和发布验收仍未完成。**

## 来源与边界

- Xiaomi《Xiaomi Log Profile》White Paper，December 2024，本地 `research/colour/2026-09-23/extracted/xiaomi-aces/02-Mi-Log_Whitepaper.pdf`，SHA-256 `d80d9a237e7602d5896092bb8e935095dd5d9d6fd46aca60a57470846d92c340`。文档版本历史包含 2024-12-17 的参数更新；本段按该版本第三章公开的第三方实现公式。
- 白皮书明确 Mi-Log 面向至少 10-bit 编码，色域原色和白点采用 BT.2020/D65；运行时复用已有 `rec2020` 解析色域，不打包 Xiaomi 官方 LUT、DCTL、`.labin` 或等价采样表。硬件编码曲线与第三方公式分开处理。

冻结常数：`R0=-0.09023729`、`Rt=0.01974185`、`c=18.10531998`、`gamma=0.09271529`、`beta=0.01384578`、`delta=0.67291850`；`Pt=c*(Rt-R0)^2`。编码分为低于 `R0` 的零段、`R0...Rt` 的平方段和 `Rt` 以上的 `log2` 段；解码分为负值钳到 `R0`、`0...Pt` 的平方根段和 `Pt` 以上的 `2^` 段，严格保留原文边界语义。

## 契约先行与实现

先写 `MiLogContractsTests` 的三段样本、负输入、非有限输入和 Rec.2020 线性曝光计划。首次 Release 编译因 `MiLogTransfer` 和稳定 ID 不存在而失败，错误见 `/tmp/lutcalc-milog-contract-red-20260925.log`。随后接入 Swift 传递函数、计划分支、目录登记及 CLI `milog-exposure` 入口。

独立 Python 读回器使用 80 位 `Decimal`，按“解码→曝光 +1→线性输出”计算每个 CUBE 轴点，检查结构、有限值、节点顺序和 `2e-12` 尺度化误差门槛；已加入集中批量入口。
