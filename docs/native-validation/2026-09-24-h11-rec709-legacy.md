# H11 Rec.709 旧兼容曲线阶段验收

日期：2026-09-24。状态：标量及最小曝光计划子集通过；H11/CORE-03、完整 Rec.709 工作流和两端 App 尚未完成。

## 语义与来源

[ITU-R BT.709-6 第 1.2 项](https://www.itu.int/dms_pubrec/itu-r/rec/bt/r-rec-bt.709-6-201506-i%21%21pdf-e.pdf)给出 `0≤L≤1` 的源端 OETF。原生 `rec709.lutcalc-legacy.v1` 的前向正值定义域按该公式，解码阈值 `V≥0.081` 和负值/超白外推按仓库旧 `js/gamma.js:LUTGammaGam Rec709`。输入/输出与旧版一样在曲线边界显式使用 `0.9` 场景/旧线性标度适配；所有计算用 `Double`。这条曲线的名字明确包含 `lutcalc-legacy`，未把旧解码称为 ITU 唯一逆，也未实现 BT.1886 显示 EOTF。[分段空隙研究记录](2026-09-24-rec709-boundary.md)仍然有效。

## 契约先行与实现

先生成独立参照：Python `Decimal.from_float` 分别用 80/120 位评估 ITU 定义域内前向公式，舍入到 Double 后逐点一致；旧引擎验证脚本直接调用 `js/gamma.js` 注册的 `Rec709` 生成边界、负值、超白及 10/12-bit 全码解码夹具。独立 Python 路径还给同色域、曝光 +1 的最小计划生成 8 个预期输出。先写 `LUTRec709Checks` 并编译，因 `Rec709Transfer` 和稳定 ID 尚不存在而退出码 1；再实现 Swift 标量、计划和注册表。

编制参照时发现：若把输入 Double `0.018` 先精确转成十进制再与数学上的十进制 `0.018` 比较，会选择低段；Swift 与旧 JS 的 Double 字面量比较在该输入选择高段。参照脚本已改为按输入 Double 与 Double 边界选段，再用高精度十进制计算所选公式。重生成后，边界夹具与旧行为一致。没有改生产公式、阈值或冻结旧夹具来掩盖误差。

## 实际命令与误差

- 工具链：Apple Swift 6.2.1，arm64 Command Line Tools。执行 `python3 tools/native-validation/generate-rec709-reference.py` 与 `node tools/native-validation/generate-rec709-legacy-baseline.js`，均退出码 0。
- `swift build --package-path Native/Packages/LUTKit --product LUTRec709Checks` 在契约先行时退出码 1，缺少 Swift 曲线与 ID。实现后 `swift run --package-path Native/Packages/LUTKit LUTRec709Checks tests/fixtures/native-contracts/rec709-itu-reference.json tests/fixtures/native-contracts/rec709-legacy-reference.json` 退出码 0。
- `tools/native-validation/verify-native-subset.sh > /tmp/lutcalc-h11-rec709-legacy-20260924.log 2>&1` 初次退出码 0；静态原生边界覆盖 42 个 Swift 源文件，旧 Node 测试 9/9 通过，Release 包与所有子集契约通过。ITU 定义域前向最大绝对误差 `5.551115123125783e-17`；旧 JS 标量和 5,120 个 10/12-bit 全码解码最大绝对误差 `1.1102230246251565e-16`；8 点同色域曝光计划最大绝对误差 `2.220446049250313e-16`。标量门槛 `5e-15`、计划门槛 `2e-12`，均沿用既有严格预算，未降低网格、位宽或插值要求。
- `python3 tools/native-validation/verify-rec709-fixtures.py` 退出码 0；核对旧源、两份参照生成脚本及两份冻结 JSON 的 SHA-256 和 10/12-bit 样本数量。纳入子集后再次执行 `tools/native-validation/verify-native-subset.sh > /tmp/lutcalc-h11-rec709-frozen-20260924.log 2>&1`，退出码 0；上述误差结果未变。

## 未覆盖范围

ITU 官方前向只覆盖 `0≤L≤1`；负值/超白与空隙解码仅验证旧兼容版本，不能宣称更准确的标准逆。Rec.709 3D 全网格、旧完整调节链、法定范围完整导出及实际目标软件导入尚未验收，App UI 不显示该条目。完整 Xcode/iOS SDK 仍缺，XCTest、双平台 App 构建、模拟器/真机与发布门槛未执行。
