# 2026-10-02 单通道导出服务调度接通验收

## 范围与原缺陷

UI 继续暂缓。本工作包修复 `NativeExportService` 将 `LUTGenerationRequest` 转为四条 `LUT1DGenerationRequest` 时丢失 `workerCount`／`blockNodes` 的后端问题；源码所在模块名为 LUTSharedUI，但没有修改视图、界面或交互。

此前请求和曝光批量指纹保存调度参数，实际 1D 服务却使用默认 2 worker／4096 点分块。现统一由私有 `generateOneD` 转换并传递参数，保留计划、域、用户 LUT／后置插值政策及显式覆盖授权。批次覆盖入口同样使用该路径。不会将 3D cubeSize 当成 1D 长度。

| --- | --- | --- |
| SPI1D | 1024 | 61 |
| ILUT | 16384 | 964 |
| OLUT | 4096 | 241 |
| Assimilate `.lut` | 4096 | 241 |

Double 计算、曲线／色域算法、格式量化、插值、位深、网格、`2e-12` 门槛和项目 schema 15 均保持原有定义。不是提高精度或完成全部格式的新算法工作包。

## 真实磁盘、独立定义与确定性

四种格式 × worker 1／4 × 分块 1／17／4096／Int.max，共 **32 个实际文件**。源请求明确使用 33³ 设置，而每条 1D 路由保持上述固定长度。Int.max 只作为超出完整长度的单块提示，不分配该大小缓冲区；实际按剩余节点数生成。

采用同 Rec.2020 的 Linear scene 恒等链，全文件解析读回 **614,400 通道**，独立定义为 `i/(size−1)`；整数格式的预期是精确 code i，不引用 TransformPlan 输出作为预期。最大／RMS／P99 都为 **0**。同格式全部 worker／分块组合的完整文件字节相同，包含头部与样本顺序。数值验证没有降低格式采样长度或精度。

另有实际 SPI1D 用户 LUT 后置测试：三通道独立缩放 1／0.5／0.25，全 1024 点解析读回相等；原始 LUT 快照保留。四个真实单项曝光批次经覆盖政策重载导出，完成节点数、worker 4／block 17 和实际报告块数均核对。此处批次曝光为 0，仅验证调度接线；非零曝光独立参照保留此前[曝光批量阶段](2026-10-02-exposure-batch.md)及本次完整回归。

## 乱序窗口与真实取消

- 对每条服务路由固定阻塞 block 0；收取 block 1…7 后才释放 block 0。实际前七个收取索引的集合为 1…7，第八个是 0，待写结果峰值固定 **8=2×workerCount**。随后全部文件按索引有序提交，解析后全节点仍满足独立恒等定义。收取顺序随任务调度变化，保存实际序列而不伪造统一顺序。
- 对四条路由分别阻塞首块，确认至少一个后续结果已经实际收取后，调用真实 `Task.cancel()` 并释放门控。生成任务抛 CancellationError，未调用成功报告观察，目标及所有任务暂存文件不存在。
- 原有格式限制、默认拒绝覆盖、授权覆盖及本地替换保护由完整回归继续核对。本阶段没有真实提供商授权／崩溃或设备取消预算证据。
