# Fujifilm F-Log2 传递函数独立参照（研究记录）

日期：2026-09-25。范围仅为 F-Log2/F-Log2 C 的编码与解码；色域矩阵、预设和设备验收另行处理。本记录不代表 Swift 实现已通过验收。

## 来源与版本

- 富士 [F-Log2 Data Sheet Ver.1.1](https://dl.fujifilm-x.com/technical-data/F-Log2_DataSheet_E_Ver.1.1.pdf)，本地 `research/colour/2026-09-23/whitepapers/fuji-flog2-v1.1.pdf`，SHA-256 `0aadf0c504dc374c3e19ee82bb67576cce3d28f603938000e14d84db1f2129cc`，第 2-3 节。
- 富士 F-Log2 C Data Sheet Ver.1.0 给出相同传递函数；官方 F-Log2 C IDT Ver.1.10 的 CLF 使用相同对数常数与线性切点，CTL 使用相同解码常数和 `0.100686685370811` 切点。CTL 在等于切点时走线性段（`>`），数据表在等于切点时走对数段（`>=`）；此单点差异约 `4.03e-9` 场景线性值。测试应以声明的版本和分支为准。
- 旧版 `js/gamma.js` 的本次 SHA-256 为 `250017d8efe758f3555148ba9fcb923698add0ac7d9380fa290716eb98e0821e`。旧行为应作为独立的兼容参照，不能覆盖原厂公式。

## 原厂公式

设 `x` 为场景线性反射率，`y` 为 data 范围 F-Log2 编码值，`a=5.555556`、`b=0.064829`、`c=0.245281`、`d=0.384316`、`e=8.799461`、`f=0.092864`、`cut1=0.000889`、`cut2=0.100686685370811`。常数按数据表原样使用，不能再补位。

```text
encode(x) = x >= cut1 ? c * log10(a*x+b) + d : e*x + f
decode(y) = y >= cut2 ? (10^((y-d)/c) - b)/a : (y-f)/e
```

数据表给出输出及输入编码范围 `0...1`。完整 10-bit data 码遍历的解码可产生负场景值（例如 `decode(0)=-0.010553373666864368...`）；不得擅自夹到零。编码高于 1 的场景值亦可用于曲线数值验证，但需单独声明扩展域。

## 旧 JS 映射与兼容差异

`js/gamma.js:215-218` 的 `LUTGammaLog` 参数为 `[0.12627036, -0.011725971, 0.245281, 5.0000004, 10, 0.384316, 0.064829, 0.100686685, 0.000987778]`。通用算法见 `js/gamma.js:2479-2553`：第 8 项是编码线性切点，第 7 项是解码编码切点；第 0/1 项直接作为低段解码 `p0*y+p1`，编码反用 `(x-p1)/p0`。

旧内部线性量 `L` 与原厂反射率的关系是 `scene=0.9*L`，因为 `5.555556*0.9=5.0000004`。因此旧高段映射到场景域后与官方公式相同。低段理想参数应为 `p0=1/(8.799461*0.9)=0.126270360322195997...`、`p1=-0.092864/(8.799461*0.9)=-0.011725970740960409...`，旧参数已截断。旧编码切点 `0.000987778` 是 `0.000889/0.9=0.000987777777...` 的近似；旧解码切点 `0.100686685` 比官方少 `3.70811e-10`。在场景零点，旧编码比官方高约 `2.288423e-9`；在官方编码切点附近，旧解码可与官方相差约 `4.028e-9` 场景值。故原厂曲线和旧兼容曲线应使用不同稳定 ID、独立参照及验收门槛。

## 分段与拟冻结门槛

- 原厂小数常数使编码在 `cut1` 有向下跳变：线性外推至切点为 `0.100686720829`，对数切点为 `0.100686685370811365...`，差 `3.5458188634e-8`。解码在 `cut2` 有约 `4.0295864282e-9` 的分支跳变。不能断言精确连续、全域严格单调，亦不能在切点附近用宽松往返误差掩盖分支错误。覆盖切点及其 `nextDown`、`nextUp`，按各自分支与独立参照比较。
- 建议原厂编码与解码标量在 `0...1` 编码域、`0...1` 场景反射率域及指定的有限扩展样本上冻结 `scaledError=abs(actual-ref)/max(1,abs(ref)) <= 2e-12`，暗部和切点另报最大绝对误差及编码码值误差。该值沿用 `docs/native-swift-precision.md` 的解析曲线初始设计门槛；正式冻结前须在目标 Swift 平台证实可达。
- 旧兼容曲线直接按旧九参数和原分支复制，另对独立 JS 行为按 `scaledError <= 2e-12` 验证；不能拿原厂参考点要求旧低段在 `2e-12` 内吻合。对同域新原厂实现可按精度规范增加 `abs(new-ref) <= abs(old-ref)+B_round(x)`；`B_round` 须基于舍入敏感性预先确定，不能用 `2e-12` 直接代替。
- 10-bit 1024 与 12-bit 4096 个 data 码点、反射率切点邻域、0、18%、90%、1 与高亮扩展点均应覆盖；有效域内非有限输出为零。范围映射由独立 `CodeRange` 阶段验证，不混入曲线公式。真机测试暂缓。
