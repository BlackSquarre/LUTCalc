# H11 ARRI LogC4 / AWG4 阶段验收

日期：2026-09-24。状态：ARRI LogC4 → ARRI Wide Gamut 4（AWG4）→线性 ACES AP0 的 Double 研发链路，通过标量、10/12-bit 全码、官方公布矩阵、10 个 RGB 点和 33³/65³ CUBE 全节点验证。完整旧引擎链、设备预设及输出变换不在此结论内。

## 来源与定义

- [ARRI LogC4 Specification（2023-05）](https://www.arri.com/resource/blob/278790/f3318e8c9c65617d8c5ca3f8b3e32051/2023-05-arri-logc4-specification-data.pdf) 第 4.1 节定义场景线性分段编解码，包括负值线性支段；第 4.2 节定义 AWG4 原色；第 4.3.2 节给出 AWG4→AP0 的 CAT02 矩阵及 18 位小数。该规范还说明 LogC4 是 EI 独立曲线，设计最低量化级别为 12-bit；本次 10-bit 全码只是数学验证，不表示推荐 10-bit 归档。
- ACES [`CSC.Arri.LogCv4_to_ACES.ctl`](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/arri/CSC.Arri.LogCv4_to_ACES.ctl) 的变换 ID 为 `urn:ampas:aces:transformId:v2.0:CSC.Arri.LogC4_to_ACES.a2.v1`；研发归档 `research/colour/2026-09-24/CSC.Arri.LogCv4_to_ACES.ctl`，SHA-256 `eeabcc59ff2d44df77c103022ce3953b4115829bfad59bfb6d99edaa86ab254d`，不进入 App。ARRI PDF 通过官网在线核对，当前网络未能下载本地 PDF，故不虚构 PDF 文件哈希。
- 独立夹具由 Python Decimal 80/120 位两次运算确认一致后转 Double。矩阵采用 ARRI 规范公布值，Swift 则从 AWG4 原色及 CAT02 推导；CUBE 节点用另一套 Python float 公式与公布矩阵核对。冻结最大尺度化误差门槛 `2e-12`。

## 实际命令与误差

先写 `LUTLogC4Checks` 契约；Release 编译因缺 `LogC4Transfer`、AWG4 与预设按预期退出码 1。实现后：

- `python3 tools/native-validation/generate-logc4-reference.py --check`：退出码 0，80/120 位、全码和 10 个 RGB 点一致。
- `swift run -c release --package-path Native/Packages/LUTKit LUTLogC4Checks tests/fixtures/native-contracts/logc4-arri-reference.json`：退出码 0。标量及 10/12-bit 全码最大尺度化误差 `2.520416211642498e-15`；AWG4→AP0 官方矩阵 `6.612422193280667e-16`；10 点完整计划 `4.04121180963557e-14`。
- `node tools/native-validation/compare-logc4-legacy.js`：退出码 0。旧 `js/gamma.js` SHA-256 `250017d8efe758f3555148ba9fcb923698add0ac7d9380fa290716eb98e0821e`；明确还原旧版 `0.9` 场景标度并设 Data→Data。10/12-bit 全码解码最大旧/官方差异 `2.8340060563291876e-15`（10-bit 码值 775），11 个编码点最大 `1.3877787807814457e-17`。这只证明旧标量有效路径，没有声称完整旧管线等价。
