## 契约与实现

在[标量与最小计划阶段记录](2026-09-24-h11-rec709-legacy.md)的独立高精度点和旧引擎全码检查之上，先要求注册表存在 `rec709.legacy-exposure-one.v1`，契约运行按预期因缺少预设退出码 1。随后加入研发预设：Rec.709 旧兼容输入与输出、sRGB/Rec.709 共用 D65 原色、Data→Data、曝光 +1。CLI 从注册表取完整设置，未增加硬编码表或预打包 LUT。

另写研发用 Python 解析器，独立读回 CUBE 的网格尺寸与每行 Double 值，按 R 最快轴序反推输入；逐节点以 Python 浮点公式计算旧兼容解码、曝光及编码，报告最大/RMS/P99 尺度化误差和最差节点。该全网格 Python 路径验证序列化、轴序和最小计划的逐点结果；它与独立 Decimal 标量参照、真实旧 JS 全码参照共同构成证据，不能单独称为高精度全网格参照。解析器拒绝非有限节点；注入 `nan` 后实际退出码 1。
