# H11 Apple Log 与 Apple Log 2 阶段验收

日期：2026-09-24。状态：**ACES CTL 所定义的两条输入转换已进入 Swift 最小计划，并通过当前数值子集；H11、CORE-03、新增设备覆盖与完整迁移仍未完成。** 本项中的 Apple Log 2 属覆盖调查新增候选，单独记账，不抵消任何旧曲线或 LUT-only 功能缺失。

## 证据、版本与边界

[ACES Apple 目录](https://github.com/aces-aswf/aces-input-and-colorspaces/tree/main/apple)现已公开原始 Apple Log 和 Apple Log 2 的正反向 CTL。2026-09-23 调查时尚未取得 Apple 白皮书，因此当时将 Log 2 公式列为待取得；本次新取得的 **ACES CTL 公开了解析式**。两份输入 CTL 使用完全相同的曲线常数/分段，**但输入原色不同**：原始版为 Rec.2020；Log 2 的 CTL 列出 Apple Wide Gamut 原色。两者均以 ACES `Lib.Academy.ColorSpaces.ctl` 默认 Bradford 适应到 AP0。不得把原版 Rec.2020 色域当作 Log 2 色域；也不由此推断所有 Apple 设备/编码模式都使用同一配置。Apple Developer Downloads 白皮书仍未取得，设备适用范围另核。

## 契约与实现

先创建 `LUTAppleLogChecks` 和独立 Decimal 夹具，Release 首次编译因 `AppleLogTransfer`、两代 ID 和色域缺失失败；随后接入公式、Rec.2020/Apple Wide Gamut 原色、Bradford 预设和 CLI。`tools/native-validation/generate-applelog-reference.py` 在 80/120 十进制位计算后校对 Double 转换，固定 `scaledError ≤ 2e-12`。矩阵按公开原色计算，不使用采样表或打包厂商 LUT。

主要文件：`Native/Packages/LUTKit/Sources/LUTCore/AppleLogTransfer.swift`、`Matrix3x3.swift`、`TransformPlan.swift`、`LUTCatalog/AlgorithmCatalog.swift`、`LUTAppleLogChecks/main.swift`、`LUTReferenceCLI/main.swift`、`LUTCatalogChecks/main.swift`、`Package.swift`、`tools/native-validation/generate-applelog-reference.py`、`compare-applelog-legacy.js`、`verify-applelog-cube.py`、`verify-native-subset.sh`、`tests/fixtures/native-contracts/applelog-aces-reference.json`。研发 CLI 预设为 `applelog-linear-ap0` 和 `applelog2-linear-ap0`。当前注册表为 11 曲线、9 色域、11 研发预设。

关键 SHA-256：Swift 曲线 `fc244fab597c0129c4a9f3a3d5a1af496daf96557a8fc616d189313a2f938cce`；独立生成器 `3c4a156c2697e2bcab234b7c08fe7cc56925ceebe84c2b86a4e3359f637780c8`；冻结夹具 `d2f802e12d2378b5a56c6054f4f133710a58cea2e1585e05934e9886409195d1`；网格比较器 `b4667328f7d64416d5d93a9ca56123577ec3d1de920244b39f249e02a338bf59`。夹具还锁定了本地矩阵辅助脚本及 ACES 颜色库的哈希。
