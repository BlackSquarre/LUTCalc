日期：2026-09-25。状态：**I-Log 2026 白皮书公式、Rec.2020 身份和线性曝光计划的本地数值验证通过；H11、相机型号范围、旧 8-bit 兼容、完整迁移和发布验收仍未完成。**

## 来源与范围

- Insta360《I-Log White Paper》，June 2026，本地 `research/colour/2026-09-23/whitepapers/insta360-ilog10.pdf`，SHA-256 `20bc91f90a56b14dceae32c0d425b5d344d38aa68875a5b14b81d612b082a81d`。文档修订历史包含 2025 10-bit 曲线更新和 2026-05-20 修订；本段只接入该版本明确的 10-bit 场景线性公式。
- 白皮书明确 I-Log 使用 BT.2020 原色和 D65 白点；运行时复用已有 `rec2020` 解析色域，不打包白皮书、厂商 LUT 或采样表。旧 8-bit I-Log、机型适用范围和其他 Insta360 曲线不自动归入本 ID。

公式常数为 `alpha=5.77837328`、`beta=0.09055934`、`delta=0.623992`、`eta=0.280055`、`theta=0.01`；编码切点 `0.01104854`，解码切点 `0.154402`。编码在 `scene > cut` 走对数段，否则走线性段；解码在 `data < cut` 走线性段，否则走对数段，保留白皮书的等号分支。

## 契约先行与实现

先写 `ILogContractsTests` 的分段点、边界、非有限输入和同 Rec.2020 线性曝光计划。首次 Release 编译因 `ILogTransfer` 和稳定 ID 不存在而失败，错误见 `/tmp/lutcalc-ilog-contract-red-20260925.log`。随后接入 Swift 传递函数、计划分支、目录登记及 CLI `ilog-exposure` 入口。

独立 Python 读回器使用 80 位 `Decimal`，按“解码→曝光 +1→线性输出”计算每个 CUBE 轴点，检查结构、有限值、节点顺序和 `2e-12` 尺度化误差门槛；已加入集中批量入口。
