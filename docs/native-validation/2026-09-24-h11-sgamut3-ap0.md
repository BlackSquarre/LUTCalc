# H11 Sony S-Log3 / S-Gamut3 → 线性 AP0 阶段验收

日期：2026-09-24。状态：Sony 官方 S-Log3 / S-Gamut3（非 Cine）到线性 ACES AP0 的 Double 链路通过独立矩阵、10 个 RGB 点及 33³/65³ CUBE 全节点验证。本记录只覆盖此组合及曝光 +1。

## 来源与独立参照

- Sony 提供的 ACES [`CSC.Sony.SLog3_SGamut3_to_ACES.ctl`](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/CSC.Sony.SLog3_SGamut3_to_ACES.ctl)，变换 ID `urn:ampas:aces:transformId:v2.0:CSC.Sony.SLog3_SGamut3_to_ACES.a2.v1`，给出 S-Gamut3 原色 R `(0.730, 0.280)`、G `(0.140, 0.855)`、B `(0.100, -0.050)`、D65 `(0.3127, 0.3290)`，使用 CAT02 与 AP0。研发归档 `research/colour/2026-09-24/CSC.Sony.SLog3_SGamut3_to_ACES.ctl` 的 SHA-256 为 `a730545da675a54d69b83583a636b8b5b4272eda690bcdda909417a458a94e1d`。
- 矩阵生成方向与 CAT02 参照 ACES [`Lib.Academy.ColorSpaces.ctl`](https://github.com/aces-aswf/aces-core/blob/main/lib/Lib.Academy.ColorSpaces.ctl)，归档 SHA-256 为 `4f07503e00127b00719416d63446d9a6b504798111d94f3860eb74754b6fb00a`。两份 CTL 只存于 `research/`，不打包进入 App。
- `tools/native-validation/generate-slog3-ap0-reference.py` 按 CTL 另行用 Python Decimal 的行向量及伴随矩阵逆生成矩阵和 10 个 RGB 点；80/120 位结果先对齐再转 Double。新夹具 `tests/fixtures/native-contracts/slog3-sgamut3-ap0-reference.json` 与现有 Cine 夹具独立，冻结尺度化阈值 `2e-12`。CUBE 逐节点检查使用夹具矩阵和单独的 Python S-Log3 解码路径，未调用 Swift 矩阵实现。

## 实际验证

Apple Swift 6.2.1，arm64 macOS Command Line Tools；Python 3.14.6。先加入需要 `sonySGamut3` 色域与预设的契约，Release 编译按预期因两者缺失退出码 1；实现后以下检查通过：

- `python3 tools/native-validation/generate-slog3-ap0-reference.py --check` 与 `--gamut gamut3 --check` 均退出码 0；未改变原 Cine 夹具。
- `swift run -c release --package-path Native/Packages/LUTKit LUTSLog3Checks <Sony 夹具> <旧兼容夹具> <Cine→AP0 夹具> <S-Gamut3→AP0 夹具>` 退出码 0。新矩阵最大尺度化误差 `2.1869446045933945e-16`；10 个 RGB 点完整计划最大尺度化误差 `1.1112638587107426e-14`。
