# LUTCalc 原生重写：实现 AI 交接入口

日期：2026-09-23。目标：macOS/iOS 全 Swift 原生，内置颜色转换全部算法实现，精度不低于既有有效实现。**本轮完成了复杂部分的设计细化、旧行为复现和基础验收数据；尚未实现 Swift App，也未取得运行性能提升。**

## 1. 阅读顺序

1. 根目录 `AGENTS.md`、如存在则读 `codex.md`。
2. 本文件：决策、工作包、当前缺陷和阻塞项。
3. [原生总体设计](native-swift-design.md)：模块、平台、完整功能范围。
4. [数值内核契约](native-swift-numeric-contracts.md)：类型、19 阶段处理顺序、矩阵、范围、插值和求根。
5. [运行与文件契约](native-swift-runtime-contracts.md)：并发、取消、内存、解析器、文件事务和项目 schema 校验。
6. [精度规范](native-swift-precision.md)、[完整任务清单](native-swift-roadmap.md)：所有验收门槛。
7. 实现具体厂商时再读[覆盖调查](colour-research-2026-09-23.md)、[纯算法审计](algorithm-only-audit.md)及相应原始资料。

遇到文档冲突时：用户最新指示优先；精度和纯算法硬约束不可放宽；本轮契约细化早期文档的概念性接口。不能凭旧代码的某个行为推翻明示契约；登记偏差并给出证据。

## 2. 最值得优化的复杂部分

| 优先级 | 部分 | 已作出的方案决定 | 能得到的改进 / 不得声称的结果 |
| --- | --- | --- | --- |
| P0 | 曲线域、legal/data、0.2/0.18、HDR 单位 | 显式类型，边界适配一次，禁止隐式裁剪 | 消除重复缩放；未逐曲线验证前不声称全量正确 |
| P0 | 计算管线和调节顺序 | 不可变 TransformPlan，19 阶段 trace，1D 独立能力 | 可定位误差、避免 UI 状态泄漏；不能按名字重排算子 |
| P0 | 纯算法来源 | 解析式与参数进入 App，参考 LUT 留在研究目录 | 满足无原始 LUT 要求；无公开公式项保留阻塞 |
| P0 | 3D 坐标与插值 | 单一 R-fast 布局，排序法四面体，域外策略分离 | 减少分支复制错误；不改变既有 interpolation ID |
| P0 | 文件读写 | 流式状态机、严格行数/数值、明确量化 | 拒绝损坏输入，减少大字符串占用；新解析器仍待实现 |
| P1 | 矩阵/CAT | 带选主元求解、条件/残差检查、按设置缓存 | 避免重复计算和脆弱求逆；融合默认关闭 |
| P1 | 求根与分析 | 先二分参照再 Brent，结构化失败、多解显式化 | 防止失败被当成颜色结果；任意 3D 逆不是已解决能力 |
| P1 | 并发与取消 | 固定快照、请求身份、有界窗口、单 writer、提交边界 | 防止乱序与取消竞态；需要调度和故障注入验收 |
| P1 | 内存/批量 | 4096 节点块起步、2 worker、有预算流式写出 | 减少峰值副本；不预报加速倍数 |
| P1 | 预览/HDR/alpha | CPU 参考、显示变换隔离、预乘语义显式化 | 避免双重颜色转换；屏幕准确度需真机测量 |
| P1 | 注册表与项目 schema 校验 | 稳定 ID、算法版本、显式资源角色、未知项拒绝 | 避免升级静默换曲线；不能按旧数组索引或文件名推断身份 |
| P2 | 热点性能 | 等数值基线通过再做仿射融合、SIMD、缓存调优 | 仅接受测得的收益，优化也受同一精度门槛约束 |

这些决定用于降低实现复杂度，而非缩减完整迁移范围。新 AI 不需要重新选择 CPU/GPU、内部标度、矩阵方向、LUT 轴序或随意发明默认策略。

## 3. 已确认的旧行为，不能盲目复制

复现脚本：[inspect-legacy-risks.js](../tools/native-validation/inspect-legacy-risks.js)。实际输出及参与文件哈希：[legacy-observations.json](../research/native-handoff/2026-09-23/legacy-observations.json)。这些是受控函数级复现，**不是已经完成的界面可达性和全产品影响审计**。

| ID | 源位置/条件 | 本轮结果 | 原生决策 |
| --- | --- | --- | --- |
| LEG-01 | `js/gamma.js`，`inCalcRGB`，`nul && inL && outL` | 2×2 平面中 12 个通道有 5 个与预期不同；已为通道偏移的 j 再乘 3 | 统一网格索引，空变换按明确范围语义生成；不复刻错误索引 |
| LEG-02 | `js/lut-cube.js`，声明 2 行、实际 1 行 | 解析器返回成功，缺行部分留下零 | 行数不等立即失败 |
| LEG-03 | 同解析器，数值行为 `0 Infinity 0` | 接受并保存 Infinity | 拒绝所有非有限值并给出行号 |
| LEG-04 | `js/brent.js`，常量 f(x)=1，目标 0 | 无根却返回 -65536 | 返回 notBracketed，数值不得进入 LUT |
| LEG-05 | `js/brent.js`，求 x²=2 | VM 全局新增 c、d | 求解器只使用局部状态，不能跨任务共享可变字段 |
| LEG-06 | `js/lut.js`，`LUTSpline` 批量包装 | RGBCub/RGBLin 因 out 未定义抛错，RGBTet 缺失；RGBLin 定义重复 | 统一标量/批量接口并分别测试；当前 UI 可达性尚未确认 |
| LEG-07 | `js/colourspace.js`，`calc` 曝光分支 | NaN 被改成 0，非有限错误被隐藏 | 有效域遇到非有限即失败，保留阶段/输入诊断 |

还有两类已见代码风险但未作为本轮新增端到端 bug 定性：`mInverse` 只判断 det===0；旧 `.labin` 对超出 ±1.99 的样本做限制。前者需条件数/残差检查，后者是有损旧格式边界，迁移时均需明确处理。

旧引擎的错误结果只能放入“已知偏差”报告，不能成为新引擎的正确预期。若后续修复旧 JS，也必须同步三个手工 bundle 并新增对应回归；本轮未改动这些生产源文件。

## 4. 小工作包与固定顺序

状态含义：“可开始”表示规范/输入足够，不表示已实现；“依赖完成后”不能跳过前置验收；“研究阻塞”不交给实现 AI 猜公式。完成一个工作包后保留报告，继续用户已授权范围内的下一个可执行工作包。

| 包 | 状态 / 前置 | 本包改动范围 | 必交付与验收 | 对应原任务 |
| --- | --- | --- | --- | --- |
| H01 | 可开始 | `Native/` 工程、Package、空壳 targets | 固定工具链，两平台最小构建；无网页运行时/内置 LUT 资源；记录实际命令 | APP-01 |
| H02 | H01 后 | LUTCore 值类型、范围、网格 | 12 范围点、27 网格点、0.9 标度、端点/溢出/非有限测试 | APP-02、CORE-01/05 |
| H03 | H02 后 | 矩阵、LU、CAT、缓存 | 非对称精确样例、原色/白点、病态拒绝、D-Gamut2 既有参照 | CORE-01 |
| H04 | H02 后 | LUTFormats 的 CUBE 基础读写 | 8 个解析文件、独立读回、负值/超白、不变的小数点；不实现其他格式 | FLOW-01 |
| H05 | H02/H03 后 | 首条 D-Log2/D-Gamut2 解析链 | 完整迁入既有 D-Log2 门槛；字段/范围方向明确；无界面 Double 生成 | CORE-02/04 |
| H06 | H04/H05 后 | 最小无调节 TransformPlan、阶段 trace、导出 CLI | 非恒等链路及旧参考比较；只有恒等测试不够；更改设置不影响已建计划 | BASE-03/05、CORE-04 |
| H07 | H02 后 | 用户 LUT 三线性/四面体 | 六种轴序、相等边界、上下端点、域/域外、14 个插值参照 | CORE-06 |
| H08 | H06 后 | Jobs 与流式生成、文件服务抽象 | 1/2/4 worker、不同块尺寸、乱序窗口上限、取消/写失败注入 | FLOW-02、QA-02 |
| H09 | H01/H06/H08 后 | 最小 Mac/iOS 参数页与导出 | 一个真实请求双端导出；状态与错误正确；同时编辑/导出互不污染 | FLOW-03/06 |
| H10 | H07 后 | 单调 1D 二分/Brent 与分析基础 | 端点根、无根、平段、多解、非有限、未收敛；原数据不修改 | FULL-05 的子集 |
| H11 | H06 后按来源批次 | 有完整来源的曲线/调节批次 | 同源参数可批量生成和验证；各项仍分别记录分段 nextUp/nextDown、负数/HDR、完整 stage trace 和冻结阈值 | CORE-03、FULL-01/03/04 |
| H12 | H09 后 | 当前 schema 项目包、显式用户资源 | 未知 ID/版本、旧 schema 拒绝、移动文件、覆盖失败、多文档、设置完整往返 | APP-04、FLOW-04 |
| H13 | H09 后 | CPU 预览→系统加速预览、示波器 | 旧预览迟到结果丢弃、alpha/HDR/色彩空间、取样与显示分别验证 | FLOW-05、UI-01…07 |
| H14 | 各子项完成后 | 旧格式、cubic/外插、完整调节、设备预设 | 按原清单逐项完成；不宣称 H01–H13 已等于完整迁移 | FULL-*、QA-*、REL-* |

H11 实现前必须有该项“公式、所有参数域、方向、标度、分段与域外行为、参照、冻结阈值”。仅有名称或一份未裁决的白皮书不够。核心合同冻结后才允许改接口；接口变更需同时更新调用方、契约与相关验收，不能每个包自创一种 RGB 或范围模型。

## 5. 仍需研究/高级审查的事项

以下仍属于完整计划，不能因为实现者能力有限就删掉：

- 9 个内置资源、45 个采样注册项及间接依赖的逐项算法替代；公开定义不足时保留阻塞。
- Apple Log 2、Samsung Log 完整公式获取；vivo/Honor/OM/Z CAM/现代 D-Log M 的公开数学定义。
- OPPO O-Log2 白皮书/参考代码差异、GoPro 负值延拓、手机场景标度的裁决。
- 每个复杂旧调节的内部工作域、cubic 边界系数、跨分段反求和病态自定义色域的完整误差预算。本轮冻结调用顺序与通用契约，没有谎称已给出全部算子公式。
- 任意 3D 反求、非唯一 TF/颜色分解、完整 ACES 2 输出模型，须专项规格和独立参照后才进入实现。
- 最低设备/系统的真实性能预算、HDR/EDR 显示和所有目标软件格式兼容，需要实机证据。

遇到其中一项时，输出具体缺失资料/最小反例/受影响能力，继续其他已具备规范的工作。禁止用经验拟合、万能 Rec.709 或“看起来差不多”填补。

## 7. 本轮证据与可用命令

当前即可执行：

```sh
node tools/native-validation/inspect-legacy-risks.js
python3 tools/native-validation/generate-contract-fixtures.py
node tools/native-validation/verify-contract-fixtures.js
```

- 复现脚本输出观察报告，不把已知旧缺陷转成必须继续存在的通过条件。

- 后续每包在 `docs/native-validation/` 写中文验收记录，记录源码/夹具哈希、工具链、平台、实际命令与未覆盖范围；目录待首个实现包创建。
